# 任务管理

`tasks/` 中每个文件代表一个可以独立实现和验收的工作单元。产品与架构事实必须写入 `docs/`，不能只存在于任务文档。

## 状态

`Draft → Ready → In Progress → Review → Verified → Completed`

只有 `Ready` 任务可以开始实现。完成后移入 `tasks/completed/`，保留范围、验收结果、验证命令和有价值的交接信息。

## 任务必须包含

- 目标和用户/工程价值；
- 相关权威文档；
- 包含和排除范围；
- 可逐条验证的验收标准；
- 预期文件范围；
- 验证命令；
- 风险、依赖和完成记录。

## 任务拆分原则

- 一个任务只包含一个主要变化；
- 不把 UI、模型接入、评测和打包混在一个任务；
- 先建立接口和测试替身，再接入重型模型；
- 发现新需求时创建后续任务，不在当前任务静默扩展；
- 任务结束时执行仓库清理清单。
