# 功能与非功能需求

状态：Accepted
最后审阅：2026-07-30

## 目的

本文是产品强制行为的权威来源。任务、规格、测试和验收报告应引用需求 ID，而不是复制需求正文。产品愿景解释目标，用户工作流解释操作顺序，本文回答系统必须做到什么。

## 优先级

- `Must`：对应里程碑完成前必须满足；
- `Should`：默认应满足，不能满足时必须记录原因和后续任务；
- `Could`：允许实现，但不得挤占当前 `Must` 范围。

## 图片输入

| ID | 优先级 | 需求 |
|---|---|---|
| FR-INPUT-001 | Must | 用户可以从本地文件系统选择一张受支持的图片。 |
| FR-INPUT-002 | Must | UI 阶段支持将图片拖入界面；剪贴板粘贴为 Should。 |
| FR-INPUT-003 | Must | 系统应用 EXIF 方向且不修改源文件。 |
| FR-INPUT-004 | Must | 无效或无法解码的输入产生可理解、可恢复的错误。 |

## 自动提取

| ID | 优先级 | 需求 |
|---|---|---|
| FR-EXT-001 | Must | 系统可以在无用户标注时生成主要物品候选。 |
| FR-EXT-002 | Must | 最终结果包含连续 Alpha，而不是仅有二值 Mask。 |
| FR-EXT-003 | Must | 最终主体 RGB 来源于输入图片，不由生成式模型重绘。 |
| FR-EXT-004 | Must | 处理流程保留被选主体的真实内部孔洞和独立组成部分。 |
| FR-EXT-005 | Should | 当系统无法可靠确定一个主要物品时，请求用户选择而不是静默确认。 |

## 交互修正

| ID | 优先级 | 需求 |
|---|---|---|
| FR-COR-001 | Must | 用户可以添加表示保留的正向提示。 |
| FR-COR-002 | Must | 用户可以添加表示删除的负向提示。 |
| FR-COR-003 | Must | 用户可以撤销和重做修正提示。 |
| FR-COR-004 | Must | 重新处理使用当前有效提示，并重新生成受影响的分割和 Alpha。 |
| FR-COR-005 | Should | UI 阶段支持点击和框选；涂抹在交互验证后纳入具体里程碑。 |

## 预览与导出

| ID | 优先级 | 需求 |
|---|---|---|
| FR-PREVIEW-001 | Must | UI 阶段提供透明棋盘格、白色和黑色预览背景。 |
| FR-PREVIEW-002 | Must | UI 阶段支持适应窗口和 100% 像素检查。 |
| FR-EXPORT-001 | Must | 系统导出可解码的 straight-alpha RGBA PNG。 |
| FR-EXPORT-002 | Must | 默认输出尺寸等于修正 EXIF 方向后的输入尺寸。 |
| FR-EXPORT-003 | Must | 默认不覆盖源文件。 |
| FR-EXPORT-004 | Must | 预览背景不进入导出像素。 |

## 本地性、质量与可维护性

| ID | 优先级 | 需求 |
|---|---|---|
| NFR-LOCAL-001 | Must | 图片和正式推理不发送到外部服务。 |
| NFR-LICENSE-001 | Must | 每个第三方代码依赖和模型权重分别记录来源、版本及许可证。 |
| NFR-QUALITY-001 | Must | 默认质量优先，不为缩短时间静默降低输出尺寸或跳过质量阶段。 |
| NFR-QUALITY-002 | Must | 影响 Alpha 的变更使用固定、版本化评测集检查回归。 |
| NFR-TEST-001 | Must | 模型接口支持测试替身，使普通单元测试无需加载真实大模型。 |
| NFR-ARCH-001 | Must | UI 和应用流程不直接依赖具体第三方模型实现。 |
| NFR-RECOVERY-001 | Should | 可恢复错误保留已有输入、提示或结果，避免用户无必要地重新操作。 |

## 追踪规则

- 当前任务只需引用与范围相关的 ID，不复制整张需求表；
- 需求文字或优先级改变时，同一变更必须检查相关验收标准、任务和 ADR；
- 需求进入实现前，任务必须说明如何验证；
- 新需求必须先加入本文或明确的功能规格，再创建实现任务；
- 当前范围之外的内容以[`out-of-scope.md`](out-of-scope.md)为准。
