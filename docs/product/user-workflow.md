# 用户工作流

状态：Accepted
最后审阅：2026-07-30

## 工具形态

工具采用本地 Web 界面：启动本机进程后在浏览器中操作，图片和模型推理均保留在本机。原型可采用快速 UI 框架，稳定交互可以在后续里程碑中演进，但用户流程保持不变。

## 主流程

1. 用户启动工具并等待模型就绪。
2. 用户拖入、粘贴或选择一张图片。
3. 工具自动识别主要物品并依次完成分割、Alpha 精修和结果合成。
4. 用户在透明棋盘格、白色或黑色背景上查看结果，并可缩放到 100% 检查。
5. 结果正确时，用户保存原始分辨率透明 PNG。
6. 结果错误时，用户进入修正模式，通过正向点击、负向点击、框选或涂抹表达意图。
7. 工具重新分割受影响区域并重新生成 Alpha，用户再次检查和保存。

## 关键状态

```text
空闲 → 已导入 → 处理中 → 已完成 → 已保存
                         ├→ 需要用户选择 → 修正 → 处理中
                         └→ 失败 → 重试或更换输入
```

## 默认行为

- 单图导入后自动处理；
- 默认最高质量模式；
- 默认自动选择主要物品及与之相关的视觉部分；
- 默认不覆盖源文件；
- 默认文件名为 `<原文件名>_transparent.png`；
- 默认保留修正方向后的原始尺寸。

## 失败与歧义

- 多个主体同样显著：请求用户点击一个或多个物品；
- 未找到主体：提供点击和框选入口；
- 显存不足：优先减小切块、顺序加载或回退 CPU，不主动降低输出尺寸；
- 导出失败：保留内存中的处理结果并允许更换目录；
- 修正不理想：保留提示历史，支持撤销、重做和重新运行。

## 第一版交互范围

必须具备单图导入、自动提取、原图/结果预览、预览背景切换、缩放、保存和基础修正闭环。批处理、独立阴影层、项目历史和原生安装包不属于第一版。

本文件描述用户旅程，不作为每项行为的唯一验收来源；强制行为及其编号见[功能与非功能需求](requirements.md)。
