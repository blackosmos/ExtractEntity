# 仓库文件更新与清理原则

状态：Accepted
最后审阅：2026-07-30

## 目标

仓库应保留能够解释当前产品、支撑当前实现、验证当前行为或记录重要历史决策的信息。减少重复、过期和纯过程性文件，可以降低人和 AI 的检索成本、错误上下文和维护负担。

## 权威来源原则

- 同一事实只允许一个权威文档；其他位置使用相对链接和简短摘要。
- 产品目标、架构、验收、里程碑和任务各自承担不同职责，不相互复制全文。
- 聊天记录、PR 描述和任务完成记录不能替代长期规格。
- 发现冲突时先确定权威来源并修正文档，不让 AI 自行选择更方便的版本。

## 何时更新既有文件

满足任一条件时优先更新现有文件：

- 内容仍属于原文件的职责和生命周期；
- 只是修正错误、补充约束或同步当前行为；
- 新增文件会产生第二份权威说明；
- 内容不足以被独立检索、评审或废弃。

更新时删除已经失效的段落，不在正文中长期堆叠“旧版/新版”并行描述；需要保留决策历史时使用 ADR 或 Git 历史。

## 何时新增文件

只有在以下情形新增文件：

- 存在独立、稳定的主题和明确维护责任；
- 需要独立状态、评审或生命周期，例如 ADR、功能规格和任务；
- 现有文件因职责混杂而难以导航；
- 新文件会被入口索引引用。

新增后必须更新最近的索引。禁止创建 `notes2.md`、`new-plan.md`、`final-final.md` 等含义不清的文件。

## 临时文件

临时文件包括实验输出、一次性脚本、截图、日志、性能 profile、模型下载片段和调试数据。

- 优先放在 Git 忽略目录或系统临时目录；
- 创建时明确用途、所有者和删除条件；
- 任务完成前删除，或提炼为测试、正式脚本、ADR/报告摘要；
- 不因“以后可能有用”而保留无法复现、无引用的产物；
- 不提交包含个人绝对路径、隐私图片、令牌或环境信息的文件。

## 任务和计划清理

- `tasks/` 只保留当前可执行任务；完成任务移至 `tasks/completed/`，并保留必要的验收和完成摘要。
- 被取消且没有历史价值的任务删除；影响范围决策的取消原因提炼到 ADR 或计划中。
- 临时实施计划在任务完成后合并为完成摘要，不继续作为现行架构说明。
- `current-milestone.md` 只描述当前阶段；结束后保存简短结果，并切换到下一里程碑。

## 文档废弃

- 有替代文档的长期决策记录标记为 `Superseded` 并链接替代项；
- 无独立历史价值的过期操作说明直接删除，由 Git 保存历史；
- 不允许两个 `Accepted` 文档同时定义冲突规则；
- 重命名或移动文档时同步所有链接和索引。

## 代码与资产清理

删除或替换功能时同时检查：

- 无调用代码、兼容层、feature flag 和导出符号；
- 对应测试 fixture、快照和黄金结果；
- 不再使用的依赖、配置、环境变量和脚本；
- UI 文案、截图、帮助内容和规格；
- 缓存目录、模型权重说明与迁移代码。

兼容代码必须有明确保留原因和删除条件。禁止无限期保留没有调用者的“备用实现”。

## 自动化防噪声

项目进入实现阶段后，应逐步加入：

- `.gitignore` 覆盖模型权重、缓存、输出和本机环境；
- 格式化、lint、类型检查和测试；
- Markdown 链接检查；
- 未使用依赖和死代码检查；
- 大文件和敏感信息检查；
- 可重复生成的报告不提交，仅提交摘要或 manifest。

## 每个任务结束前的清理清单

1. `git status` 中是否只有预期文件？
2. 是否存在重复说明或第二权威来源？
3. 是否残留调试日志、注释代码、TODO、临时脚本或截图？
4. 是否出现无引用文件、孤立文档或失效链接？
5. 是否应删除已经不用的依赖、配置和测试资产？
6. 文件名和目录是否表达稳定职责？
7. 是否把应长期保留的结论从任务日志提炼到了规格或 ADR？
8. 是否更新索引、任务状态和已知限制？

## 定期整理

每个里程碑结束时进行一次仓库审计：

- 删除缓存、生成物和过期临时材料；
- 检查 `Draft`、`TODO`、`deprecated` 和 `Superseded` 项；
- 检查无引用文档、未使用依赖和失效命令；
- 合并重复说明；
- 确认 README、文档地图和当前里程碑反映真实状态；
- 将审计结论记录为简短里程碑结果，而不是长期堆积完整日志。
