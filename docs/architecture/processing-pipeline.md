# 图像处理流水线

状态：Accepted
最后审阅：2026-07-30

## 标准流程

```text
输入文件
→ 解码与 EXIF 方向修正
→ 内部 RGB 图像
→ 自动主体候选
→ 候选选择或用户提示修正
→ 粗 Mask
→ 自适应 Trimap
→ Alpha Matting
→ 原图分辨率边缘精修
→ Alpha 校验
→ 原始 RGB + Alpha 合成
→ RGBA PNG
```

## 不变量

- 源文件永不被修改。
- 除预览和模型推理副本外，最终结果保持修正方向后的原始尺寸。
- 中间过程不得通过 JPEG 落盘。
- Mask 和 Alpha 在内部使用有定义的类型、形状和数值范围。
- 最终 RGB 来源于原图，不由生成式模型重绘。
- 已知前景、已知背景和未知边缘在 Matting 阶段具有明确含义。

## 阶段职责

### 解码与规范化

读取支持的图片格式，应用 EXIF 方向，生成统一 RGB 表示并记录原始元数据。颜色管理的具体策略在实现前通过任务或 ADR 确定。

### 主体候选

默认模型生成一个或多个概率 Mask。候选必须包含原图输入尺寸、概率 Mask
和模型来源身份，不得直接写出最终文件。不同模型的原生分数含义不同，因此正式候选契约
不强制一个不可比较的通用置信度或告警字段；需要这些信息时应先定义跨模型语义。

### 交互修正

SAM 2 等交互模型接收正负点或框。用户提示表达“保留/删除”的意图，不要求用户精确描边。

### Trimap 与 Matting

粗 Mask 生成自适应 trimap，ViTMatte 等模型输出连续 Alpha。边缘宽度应与图像尺寸和局部结构相关，不能对整图统一羽化。

M0 骨架使用可替换的确定性阈值基线验证组件协作：概率小于或等于
`background` 时是已知背景，概率大于或等于 `foreground` 时是已知前景，
两阈值之间是未知区域。两阈值均为 `[0, 1]` 内的有限浮点数，且
`background < foreground`。该规则不包含形态学和边缘自适应，不代表最终质量策略。

M0 同步单图内存流程严格按以下顺序执行：

```text
SegmentationModel
→ 应用层分割输出校验
→ ProbabilityMask 阈值转换
→ MattingModel
→ 应用层 Alpha 输出校验
→ ExtractionResult
```

任一模型异常或边界校验错误原样传播，不生成部分成功结果。该流程不读写文件，
也不负责选择、加载或重试模型。

### 全分辨率精修

仅对不确定边缘进行重叠切块处理，合并时避免接缝；质量优先模式允许增加耗时，但不得静默降低输出尺寸。

### 合成与导出

将经过验证的 Alpha 与原始 RGB 合成为 straight-alpha RGBA PNG。预览背景仅用于检查，不写入输出。

8-bit RGBA 合成边界使用 packed row-major `RGBARGBA...` 表示。RGB 逐字节来自
`ImageDocument`，即使 Alpha 为 0 也不预乘或清零隐藏 RGB。内部 `AlphaMatte` 仍保持
`[0, 1]` 浮点精度；只在 8-bit 输出边界按 `floor(alpha * 255 + 0.5)` 执行
round-half-up 量化，避免依赖 Python bankers rounding。PNG 编码与文件保存由后续任务负责。

## 降级原则

降级必须可见且可记录。优先顺序为减小切块、顺序加载模型、CPU 回退；只有用户明确选择时才降低处理分辨率。
